题型 1　看 cwnd 图：慢启动、拥塞避免、Reno vs Tahoe ★★★

发送方受 $\text{LastByteSent} - \text{LastByteAcked} \le cwnd$ 限制，所以 $\text{速率} \approx cwnd / RTT$。cwnd 随感知到的拥塞变化：

  • 慢启动：开始 cwnd = 1 MSS，每 RTT 翻倍（实现：每个 ACK 加 1 MSS）。「慢」是起点低，增长是指数的。
  • 拥塞避免：cwnd 到 ssthresh 后，每 RTT 加 1 MSS（AIMD 的加性增）。
  • 丢包时 ssthresh = 当时 cwnd 的一半（超时和 3 个重复 ACK 都更新）。
丢包信号TCP RenoTCP Tahoe
超时cwnd = 1，慢启动到 ssthreshcwnd = 1
3 个重复 ACKcwnd 减半，然后线性（快速恢复）cwnd = 1（不区分）

Reno 对重复 ACK 手下留情：重复 ACK 说明后面的段都到了，拥塞不严重；超时说明什么都没回来，更严重。

看图解法
  1. 每轮翻倍的区间 = 慢启动；每轮 +1 的区间 = 拥塞避免。
  2. cwnd 从 X 掉到 X/2 → 3 个重复 ACK（Reno）；掉到 1 → 超时（或者是 Tahoe）。
  3. 初始 ssthresh = 慢启动停下来的那个值。之后 ssthresh = 丢包前 cwnd / 2。
  4. 「第 k 个段在哪一轮发」：逐轮累加 cwnd。慢启动前 n 轮共 $2^n - 1$ 个；进入线性后每轮只多 1。

题型 2　推 Seq / ACK 号 ★★★

  • 序号按字节编号，不是按段：是这个段第一个数据字节的编号。
  • ACK 号 = 期望收到的下一个字节；累积：ACK = n 表示 n 之前全收到。
  • ACK 可以捎带在数据段里。收到乱序段怎么办：TCP 规范没规定，由实现决定（实际都缓存）。
$$\text{我的下一个 Seq} = \text{我上一段 Seq} + \text{长度}\qquad \text{我发的 ACK} = \text{对方上一段 Seq} + \text{长度}$$

例题（讲义 Telnet）

A 敲一个字母 'C'（1 字节），B 回显。A 起始序号 42，B 起始序号 79。

方向SeqACK数据
A → B4279'C'
B → A7943'C'（回显）
A → B4380无

TCP 段结构要点

源 / 目的端口；序号；确认号；首部长度；ACK、SYN、FIN、RST 位；rwnd（流量控制）；checksum（和 UDP 同一算法）；URG、PSH 一般不用。首部最少 20 字节。

TCP 特点：点到点（不支持多播）、可靠按序字节流（没有消息边界，应用写两次 100 字节对方可能一次读到 200）、流水线、全双工、面向连接、流量控制。MSS = 一个段里应用数据的最大字节数。

主机 A 发给 B 一个 Seq = 92、含 8 字节数据的段，B 正确收到后回的 ACK 号是？
  1. 92
  2. 93
  3. 99
  4. 100
下一个期望字节 = 92 + 8 = 100。

题型 3　TCP 重传与快速重传 ★★

发送方事件动作
收到应用数据建段发出；定时器没跑就启动（定时器给最老的未确认段）
超时只重传序号最小的未确认段，重启定时器（GBN 是重传整个窗口）
收到 ACK = yy > SendBase 就 SendBase = y；还有未确认段就重启定时器

三个重传场景（讲义）

  • ACK 丢了：A 发 92（8 B），ACK 100 丢；超时重传 92；B 丢掉重复数据，再回 ACK 100。
  • 过早超时：A 发 92（8 B）、100（20 B），ACK 还在路上就超时，重传 92；B 对重传回 ACK 120（累积）。
  • 累积 ACK 救场：ACK 100 丢了，但 ACK 120 在超时前到了 → 什么都不用重传。

接收方何时发 ACK

情况动作
按序到达，之前都已确认延迟 ACK：最多等 500 ms
按序到达，还有一个 ACK 在等立即发累积 ACK，一次确认两个
乱序到达，出现空洞立即发重复 ACK，写期望的下一个字节
填补空洞立即发 ACK
快速重传

收到同一数据的 3 个重复 ACK，立即重传最小序号的未确认段，不等超时。为什么是 3：1、2 个可能只是网络乱序。

例：A 发 Seq 100、120、140、160、180（各 20 B），120 丢。B 回 ACK 120（正常）、120、120、120（3 个重复）→ A 重传 120 → B 补上空洞，回 ACK 200。

计数陷阱

「3 个重复 ACK」= 一共收到 4 个相同的 ACK（第 1 个是正常确认）。

A 发 Seq = 92（8 字节）和 Seq = 100（20 字节），ACK = 100 丢了，ACK = 120 在超时前到达。A 要重传什么？
  1. 重传 Seq = 92
  2. 重传 Seq = 100
  3. 两个段都要重传
  4. 都不用重传
累积 ACK 120 说明之前的字节全收到了。

题型 4　流量控制 vs 拥塞控制 ★★★

流量控制：应用读得慢、发送方发得快，接收缓冲会溢出。接收方在首部写 rwnd，发送方保证在途数据 ≤ rwnd：

$$rwnd = \text{RcvBuffer} - (\text{LastByteRcvd} - \text{LastByteRead})$$
流量控制拥塞控制
保护谁接收方缓冲区网络（路由器缓冲、链路）
信号来源接收方明确告诉（rwnd）发送方从丢包、时延自己推断
变量rwndcwnd

实际发送窗口 = min(rwnd, cwnd)。TCP 拥塞控制是端到端的（网络不给反馈）；网络辅助的是 ECN、DECbit、ATM ABR（路由器给反馈）。

关于流量控制和拥塞控制，正确的是？
  1. 流量控制保护接收方缓冲区
  2. 拥塞信号由接收方写在 rwnd
  3. 发送窗口取 rwnd、cwnd 较小值
  4. TCP 拥塞控制靠端系统推断
B 说的是流量控制。

题型 5　三次握手与关闭连接 ★★

为什么两次握手不行

消息会延迟、重传、乱序，服务器分不清新请求和旧的重复请求：

  • 半开连接：旧请求在连接用完关闭后才到，服务器又建立连接，但客户端已经不在了。
  • 接受旧数据：迟到的旧数据被当成新连接的数据。

三次握手

步方向内容
1C → SSYN = 1，Seq = x（客户端 SYN_SENT）
2S → CSYN = 1，Seq = y，ACKnum = x + 1（SYNACK，服务器 SYN_RCVD）
3C → SACKnum = y + 1，SYN = 0，可以带数据（双方 ESTAB）
  • SYN 和 FIN 各占一个序号，所以是 x + 1、y + 1。
  • 第 3 步让服务器确认客户端此刻在、而且确认的是服务器新选的 y。旧 SYN 即使到了，客户端不会确认（回 RST）。
  • 建连 1 RTT，第 3 步带上 HTTP 请求，这就是 W03「建连 1 RTT + 请求 1 RTT」的由来。

关闭连接

步段客户端服务器
1C → S：FIN，seq = xFIN_WAIT_1
2S → C：ACK x + 1FIN_WAIT_2CLOSE_WAIT（还能发数据，半关闭）
3S → C：FIN，seq = yLAST_ACK
4C → S：ACK y + 1TIMED_WAIT，等 2 × 最大段寿命CLOSED

TIMED_WAIT 的原因：① 最后的 ACK 丢了时，服务器重发 FIN，客户端还能再回；② 让残留的旧段过期，不干扰下一条用同样四元组的连接。

三次握手中，客户端初始序号 x，服务器初始序号 y。SYNACK 段的确认号是？
  1. x
  2. x + 1
  3. y
  4. y + 1
SYN 占一个序号。y + 1 是第三个段的确认号。

题型 6　RTT 估计与超时 ★★

超时太短：过早超时，不必要的重传；太长：丢包后反应慢。SampleRTT 是段发出到收到 ACK 的时间，重传的段不测（分不清 ACK 是对哪次发送的）。

$$\begin{aligned} EstimatedRTT &= (1-\alpha)\,EstimatedRTT + \alpha\,SampleRTT, &\alpha &= 0.125\\ DevRTT &= (1-\beta)\,DevRTT + \beta\,|SampleRTT - EstimatedRTT|, &\beta &= 0.25\\ TimeoutInterval &= EstimatedRTT + 4\,DevRTT \end{aligned}$$

EstimatedRTT 是指数加权移动平均（EWMA），越早的样本权重按指数衰减。

例题

EstRTT = 100，DevRTT = 10，SampleRTT = 140（ms）。先用旧 EstRTT 更新 DevRTT：$0.75\times10 + 0.25\times40 = 17.5$；EstRTT $= 0.875\times100 + 0.125\times140 = 105$；Timeout $= 105 + 70 = 175$ ms。

先后顺序

先更新 EstRTT 再算 DevRTT 得 16.25、Timeout 170 ms。讲义没规定先后，两种都算一下，选项里只会有一个对得上。

EstimatedRTT = 80 ms，DevRTT = 8 ms，新测得 SampleRTT = 120 ms（先更新 DevRTT）。新的 EstimatedRTT 和 TimeoutInterval 是？
  1. 85 ms，117 ms
  2. 85 ms，149 ms
  3. 120 ms，152 ms
  4. 80 ms，112 ms
DevRTT $= 0.75\times8 + 0.25\times40 = 16$；EstRTT $= 0.875\times80 + 0.125\times120 = 85$；Timeout $= 85 + 64 = 149$ ms。

题型 7　拥塞代价、吞吐量与公平性 ★

拥塞的四个代价

场景代价
缓冲无限、不重传① 到达速率接近容量时，排队时延趋于无穷（每个连接最多 R/2）
缓冲有限、会重传② 为同样的 goodput 要多发重传；③ 过早超时让链路传同一分组的多个副本
多跳④ 分组在下游被丢，上游为它用掉的容量全浪费

$\lambda_{in}$ 是原始数据速率，$\lambda'_{in}$ 是原始 + 重传（offered load），$\lambda'_{in} \ge \lambda_{in}$。

吞吐量

$$\text{平均吞吐量} = \frac34\cdot\frac{W}{RTT}\qquad \text{Mathis：}\ \frac{1.22\cdot MSS}{RTT\sqrt{L}}$$

窗口在 W/2 到 W 之间锯齿变化，平均 3W/4。例：W = 120 KB，RTT = 100 ms → 900 KB/s。10 Gbps、RTT 100 ms、1500 字节段需要丢包率 L ≈ 2 × 10⁻¹⁰，所以高速网络需要新版 TCP。

公平性

K 条连接共享 R 的瓶颈，每条平均 R/K。为什么 AIMD 公平：加性增两条同时 +1，差距不变；乘性减同时减半，差距减半，反复下去收敛到平分点。

两个漏洞
  • UDP 不受 TCP 拥塞控制约束。
  • 并行连接：已有 9 条，新应用开 1 条得 R/10，开 11 条得 11R/20 ≈ R/2。TCP 是按连接公平，不是按应用。
带宽 R 的瓶颈链路上已有 9 条 TCP 连接。一个新应用开 11 条并行 TCP 连接，它大约得到多少带宽？
  1. R/10
  2. R/20
  3. 11R/20
  4. R
共 20 条，每条 R/20，新应用拿 11 份。

题型 8　滑动窗口序号空间（W8 tutorial） ★

序号只有 {0, 1, 2, 3}，SR 窗口 3：

  • (a) pkt0、1、2 到达并确认，接收窗口移到 {3, 0, 1}；发送方接着发的 pkt0 是新分组。
  • (b) pkt0、1、2 到达，但 3 个 ACK 全丢；发送方超时重传旧 pkt0；接收窗口已是 {3, 0, 1}，把旧 pkt0 当成新的收下。

问答
最多几个未确认分组在路上3（窗口大小）

考前速记

  1. 慢启动每 RTT 翻倍（每 ACK +1 MSS），到 ssthresh 转线性；丢包 ssthresh = cwnd/2。
  2. Reno：超时 → 1，3 dup ACK → 减半；Tahoe 都回 1。图上掉一半 = dup ACK，掉到 1 = 超时。
  3. Seq 按字节；ACK = 下一个期望字节；累积 ACK。
  4. 超时只重传最老一个段；3 个重复 ACK（共 4 个相同）快速重传。
  5. rwnd 保护接收方（明确告知），cwnd 保护网络（推断）；窗口 = min。
  6. 握手 SYN(x) → SYNACK(y, x+1) → ACK(y+1，可带数据)；两次握手会半开、收旧数据。
  7. Timeout = EstRTT + 4 DevRTT；α = 0.125，β = 0.25；重传段不测。
  8. 平均吞吐 0.75 W/RTT；按连接公平；UDP 和并行连接是漏洞。
  9. 序号空间：$s \ge 2w$，{0..3} 最大窗口 2。
