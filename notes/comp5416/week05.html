题型 1　GBN vs Selective Repeat ★★★

两种流水线协议：发送方最多 $N$ 个已发未确认的分组在路上。区别在接收方怎么回 ACK、发送方怎么重传。

Go-Back-NSelective Repeat
ACK累积：ACK(n) = n 及以前全收到每个分组单独 ACK
收到乱序分组丢掉不缓存，重发最后按序收到的 ACK缓存，回这个分组自己的 ACK
定时器一个，给最老的未确认分组每个未确认分组一个
超时重传这个分组及其后所有已发出的只重传超时的那一个
序号空间至少$N + 1$$2N$
特点接收方简单，浪费带宽接收方要窗口和缓存，省带宽

走一遍：N = 4，发 pkt0–5，pkt2 丢了

时刻GBNSR
收到 pkt0、1回 ack0、ack1回 ack0、ack1
发送方收 ack0、1窗口滑动，发 pkt4、5同左
收到 pkt3、4、5全丢掉，每次重发 ack1缓存，回 ack3、ack4、ack5
pkt2 超时重传 pkt2、3、4、5只重传 pkt2
之后依次交付，回 ack2–5收到 pkt2，一次交付 2–5，回 ack2；窗口最左端直接滑到 6
解法
  1. GBN 重传数 = 从丢的那个起，到已经发出的最后一个，共几个。
  2. SR 只重传丢的那个；接收方回的 ACK 序号就是它收到的分组序号。
  3. GBN 接收方收到乱序分组时回的是最后一个按序收到的序号（这里是 ack1）。
陷阱
  • SR 接收方收到已经交付过的旧分组（序号在 $[\text{rcvbase}-N, \text{rcvbase}-1]$），仍要回 ACK：说明发送方没收到之前的 ACK，不回的话发送方窗口动不了。
  • SR 序号空间要 $2N$：太少的话分不清新分组和上一轮的重传。
  • TCP 是混合：累积 ACK、一个定时器（像 GBN），但接收方缓存乱序段、超时只重传一个段（像 SR）。
GBN，N = 4，发送方发了 pkt0–pkt5，pkt2 丢失、其余都到。pkt2 超时后发送方重传哪些分组？
  1. 只重传 pkt2
  2. pkt2 和 pkt3
  3. pkt2、3、4、5
  4. pkt0 到 pkt5
GBN 重传超时分组及其后所有已发出的分组。换成 SR 就只重传 pkt2。

题型 2　停等利用率与流水线 ★★★

利用率：发送方真正在发数据的时间占一个周期的比例。一个周期从发第一个比特，到 ACK 回来，共 $RTT + L/R$；发送方只在前 $L/R$ 里忙：

$$U_{\text{停等}} = \frac{L/R}{RTT + L/R}\qquad U_{\text{流水线}} = \frac{N\cdot L/R}{RTT + L/R}$$

例题（讲义）

1 Gbps，RTT 30 ms，分组 8000 bits。

  1. $L/R = 8000/10^9 = 8\ \mu s = 0.008$ ms
  2. $U = 0.008/30.008 = 0.00027$
  3. 吞吐量：每 30.008 ms 发 1 KB，约 33 kB/s。1 Gbps 的链路只跑出 33 kB/s：协议限制了物理资源的使用。
  4. 流水线 $N = 3$：$U = 0.0008$。占满链路要 $N = 30.008/0.008 \approx 3751$。
单位坑

$L/R$ 算出来是微秒级，RTT 是毫秒级，先统一单位再除。链路越快、RTT 越大，停等越浪费。

100 Mbps 链路，RTT = 10 ms，分组 1000 bytes，停等协议。发送方利用率约为？
  1. 0.0010
  2. 0.0079
  3. 0.0800
  4. 0.0741
$L/R = 8000/10^8 = 0.08$ ms；$U = 0.08/10.08 = 0.0079$。A 是忘了字节乘 8：$0.01/10.01$。

题型 3　多路分解：UDP 二元组 vs TCP 四元组 ★★★

多路复用（发送方）：收集多个 socket 的数据，加上含源 / 目的端口（各 16 位）的首部交给网络层。多路分解（接收方）：按首部把段交给正确的 socket。

UDPTCP
socket 标识二元组：目的 IP + 目的端口四元组：源 IP + 源端口 + 目的 IP + 目的端口
不同来源、同一目的端口进同一个 socket进不同的 socket
服务器一个 socket 服务所有客户；回复时把收到的源端口填成目的端口每条连接一个 socket；非持久 HTTP 每个请求新开一个

例题（讲义）

三个段都发往 (B, 80)：① 来自 (A, 9157)；② 来自 (C, 5775)；③ 来自 (C, 9157)。

  • TCP：三个四元组都不同 → 3 个 socket。② 和 ③ 只有源端口不同，也分开。
  • UDP：只看 (B, 80) → 1 个 socket。
上面三个段，如果服务器用 UDP 且端口为 80，进入几个 socket？
  1. 1
  2. 2
  3. 3
  4. 无法判断
UDP 只看目的 IP 和目的端口。

题型 4　Internet 校验和 ★★

算法
  1. 把段内容（含首部）看成一串 16 位整数，全部相加。
  2. 最高位产生的进位加回最低位（回卷，wraparound）。
  3. 按位取反，得到校验和。
  4. 接收方：所有 16 位字 + 校验和相加（回卷），没错时得全 1，取反为全 0。

例题（讲义）

字 11110 0110 0110 0110
字 21101 0101 0101 0101
相加（17 位）1 1011 1011 1011 1011
回卷：进位加到末位1011 1011 1011 1100（和）
取反0100 0100 0100 0011（校验和）
陷阱
  • 最容易丢分：忘了回卷。选项里会有「没回卷直接取反」的 0100 0100 0100 0100，也会有「只算到和、没取反」的结果。
  • 校验和只能检测、不能纠正，也检测不出所有错误（两个比特翻转互相抵消时和不变）。
两个 16 位字 1000 0000 0000 0001 和 1000 0000 0000 0010 的 Internet 校验和是？
  1. 0000 0000 0000 0011
  2. 1111 1111 1111 1100
  3. 1111 1111 1111 1011
  4. 0000 0000 0000 0100
相加得 1 0000 0000 0000 0011，回卷得 0000 0000 0000 0100（D 是和），取反得 C。B 是没回卷直接取反。

题型 5　rdt 1.0 → 3.0 ★★

在不可靠的 IP 上搭出可靠传输。每一版只解决一个新问题：

版本信道问题新增机制
1.0无直接发
2.0比特翻转校验和 + ACK / NAK + 收到 NAK 重传
2.1ACK / NAK 本身也会坏分组加序号（0、1 两个就够）
2.2同上去掉 NAK，只用带序号的 ACK
3.0还会丢包倒计时定时器，超时重传
  • 2.1 为什么 0、1 就够：停等协议同一时刻只有一个分组在路上，只要区分「新的」和「上一个的重复」。收到重复分组：丢掉不交付，但仍回 ACK。
  • 2.2：对最后一个正确收到的分组回 ACK。等 ACK0 却收到 ACK1，相当于 NAK，重传 pkt0。这就是重复 ACK，TCP 快速重传用它（W06）。
  • 3.0 的四种情况：数据丢 → 超时重传；ACK 丢 → 超时重传，接收方发现重复、丢掉、再回 ACK；ACK 只是来晚（过早超时）→ 重传，发送方会收到两个同号 ACK，第二个忽略。
rdt 各版本与新增机制的对应，正确的是？
  1. rdt 2.0：校验和 + ACK/NAK
  2. rdt 2.1：给分组加上序号
  3. rdt 2.2：在 2.1 上增加 NAK
  4. rdt 3.0：加入超时定时器
rdt 2.2 是去掉 NAK，用带序号的 ACK 代替。

题型 6　UDP 与传输层概念 ★★

  • 传输层提供进程到进程的逻辑通信，只跑在端系统上，路由器不管传输层。网络层是主机到主机，尽力而为。
  • 传输层数据单元叫 segment。TCP 和 UDP 都不保证时延和带宽。
  • UDP：无修饰，可能丢、可能乱序；无连接。
为什么要 UDP（四个理由）
  1. 不建连接，少一次握手的时延。
  2. 简单，收发双方不维护连接状态。
  3. 首部小：8 字节（TCP 至少 20）。
  4. 没有拥塞控制，想发多快发多快。

用途：流媒体、DNS。要可靠就在应用层自己做（QUIC，W12）。

UDP 首部：源端口、目的端口、length（含首部的段长，最小 8）、checksum，各 16 位。

为什么有些应用选择 UDP？
  1. 不需要建立连接，时延小
  2. 首部只有 8 个字节
  3. 没有拥塞控制，发送速率自定
  4. UDP 保证按序交付数据
UDP 不保证按序，也不保证可靠。

考前速记

  1. GBN：累积 ACK、丢乱序、一个定时器、重传后面全部；SR：单独 ACK、缓存、每包定时器、只重传一个。N = 4 丢 pkt2：GBN 重传 4 个，SR 1 个。
  2. SR 对已交付旧分组仍回 ACK；序号空间 停等 2、GBN $N+1$、SR $2N$。
  3. $U = \frac{L/R}{RTT+L/R}$，流水线乘 $N$；1 Gbps、30 ms、8000 bits → 0.00027。
  4. UDP 二元组（目的 IP + 端口），TCP 四元组。
  5. 校验和：相加、回卷、取反；接收方得全 1；只检测不纠正。
  6. rdt：2.0 校验和 + ACK/NAK；2.1 序号；2.2 去掉 NAK；3.0 定时器。
  7. UDP：不建连、无状态、8 字节首部、无拥塞控制；TCP、UDP 都不保证时延和带宽。
