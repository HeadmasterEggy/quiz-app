题型 1　DNS 迭代 / 递归查询 ★★★

层次结构

服务器管什么
根顶端，知道各 TLD 服务器在哪。逻辑上 13 个（a–m），每个在全球有很多镜像
TLDcom、org、edu、net 和国家域 uk、au，知道每个域的权威服务器在哪
权威组织自己的 DNS 服务器，存本组织主机的「名字 → IP」
本地每个 ISP 都有，也叫默认名字服务器。主机的查询先发给它，它代为去问。严格来说不属于层次结构

迭代查询：8 步（主机 cis.poly.edu 查 gaia.cs.umass.edu）

  1. 主机 → 本地 DNS：问 gaia.cs.umass.edu
  2. 本地 → 根
  3. 根 → 本地：「去问 .edu 的 TLD」
  4. 本地 → TLD
  5. TLD → 本地：「去问权威 dns.cs.umass.edu」
  6. 本地 → 权威
  7. 权威 → 本地：A 记录（IP 地址）
  8. 本地 → 主机：返回 IP

递归查询：每一级替你往下问，答案逐级传回（主机 → 本地 → 根 → TLD → 权威，再原路返回），也是 8 条消息，但根和 TLD 要一直参与并等结果，上层负担重。

迭代递归
被问的服务器指路：「去问它」跑腿：替你问到底
谁跑来跑去本地 DNS层次里的每一级
上层负载低高
最佳实践是（样卷 Q3.5）否

实际常见做法：主机 → 本地是递归（主机只要答案），本地 → 层次结构是迭代。

缓存与 TTL

服务器学到映射就缓存，TTL 到期删掉。本地 DNS 常缓存 TLD 地址，所以根很少被访问。缓存可能过时：主机换了 IP，TTL 到期前别人可能还拿着旧地址。

迭代查询中，本地 DNS 收到主机的查询且缓存里没有，它先去问谁？
  1. 发起查询的用户主机
  2. 另一台本地 DNS
  3. 根 DNS 服务器
  4. 权威 DNS 服务器
本地 → 根 → TLD → 权威。

记录格式 (name, value, type, ttl)：

类型namevalue例子
A主机名IP 地址(gaia.cs.umass.edu, 128.119.245.12, A)
NS域名该域权威服务器的主机名(umass.edu, dns.umass.edu, NS)
CNAME别名规范名（真名）(www.ibm.com, servereast.backup2.ibm.com, CNAME)
MX域名邮件服务器名(umass.edu, mail.umass.edu, MX)
解法：看 value 是什么

value 是 IP → A；是这个域的 DNS 服务器名 → NS；是同一台主机的真名 → CNAME；是邮件服务器 → MX。

陷阱：NS 和 A 成对出现

NS 只给了权威服务器的名字，连不上，所以 TLD 同时给一条这个服务器的 A 记录（胶水记录）。注册 networkutopia.com 时，注册商往 .com TLD 插入两条：(networkutopia.com, dns1.networkutopia.com, NS) 和 (dns1.networkutopia.com, 212.212.212.1, A)。所以「本地 DNS 问 TLD 得到几条记录」答 2。

记录 (www.ibm.com, servereast.backup2.ibm.com, ?) 的类型是？
  1. A
  2. NS
  3. CNAME
  4. MX
别名 → 规范名，是 CNAME。

题型 3　文件分发时间：C/S vs P2P ★★★

把大小 $F$ 的文件从一台服务器分发给 $N$ 个用户。$u_s$ 是服务器上传速率，$u_i$ 是用户 $i$ 的上传速率，$d_{\min}$ 是最慢的下载速率。

$$D_{cs} \ge \max\left\{\frac{NF}{u_s},\ \frac{F}{d_{\min}}\right\}$$
  • $NF/u_s$：服务器要亲自发 $N$ 份。随 $N$ 线性增长，没有上限。
  • $F/d_{\min}$：最慢的用户下完一份。
$$D_{P2P} \ge \max\left\{\frac{F}{u_s},\ \frac{F}{d_{\min}},\ \frac{NF}{u_s + \sum u_i}\right\}$$
  • $F/u_s$：服务器至少发出一份（不是 $N$ 份，其余由用户互传）。
  • $NF/(u_s + \sum u_i)$：总共要收 $NF$ 比特，全系统总上传能力是服务器加所有用户。

为什么 P2P 能扩展：每来一个用户也多一份上传能力。所有人上传都是 $u$ 时，$N \to \infty$ 时 $\dfrac{NF}{u_s + Nu} \to \dfrac{F}{u}$，趋于常数；C/S 是一条一直往上的直线。

解法步骤
  1. 把每一项都算出来（统一单位：Mbit 和 Mbps，或 Gbit 和 Gbps）。
  2. 取最大的那一项，它就是答案，也是瓶颈。
  3. 瓶颈判断：$NF/u_s$ → 服务器上传；$F/d_{\min}$ → 最慢下载；第三项 → 全系统上传能力。

例题（Midterm 练习）

$F = 2400$ Mbit，$N = 12$，$u_s = 90$ Mbps，$\sum u_i = 190$ Mbps，$d_{\min} = 25$ Mbps。

各项答案
C/S$12\times2400/90 = 320$；$2400/25 = 96$320 s（服务器上传）
P2P$2400/90 = 26.7$；$96$；$28800/280 = 102.9$102.9 s（总上传能力）
最常见的错

P2P 第一项写成 $NF/u_s$。

$F = 1$ Gbit，$N = 20$，$u_s = 50$ Mbps，每个用户上传 10 Mbps、下载 100 Mbps。P2P 最短分发时间约为？
  1. 20 s
  2. 80 s
  3. 400 s
  4. 10 s
$F/u_s = 1000/50 = 20$；$F/d_{\min} = 10$；$NF/(u_s+\sum u_i) = 20000/(50+200) = 80$。取最大 80 s。C 是 C/S 的 $NF/u_s$。

题型 4　BitTorrent ★★

  • torrent：交换同一文件分块的一群用户；tracker：只记录有哪些用户。文件切成 256 KB 分块。
  • 新用户向 tracker 注册，拿到用户列表，和一部分邻居连接；边下边传；用户随时来去（churn）。
策略规则为什么
rarest first（请求）先要邻居里最少人有的块稀有块持有者一走就拼不出文件
tit-for-tat（发送）只给当前给我发得最快的 4 个人发，其余 choked；每 10 秒重评激励多上传
optimistic unchoke每 30 秒随机挑一个人发新用户还没东西可传，进不了前 4；给他起步机会，也发现更好的伙伴
陷阱

10 秒是重评前 4 名，30 秒是乐观疏通，别弄反。tracker 不存分块。

乐观疏通（optimistic unchoke）的主要作用是？
  1. 加快最稀缺分块在网络中的复制
  2. 让新用户得到块，也发现更好的伙伴
  3. 防止 tracker 因请求过多而过载
  4. 减小每个分块的大小以加快下载
新用户还没有块可上传，靠 tit-for-tat 永远进不了别人的前 4 名。

题型 5　DHT 后继 ★★

DHT：分散在很多用户上的 (key, value) 数据库。key 哈希成 $[0, 2^n - 1]$ 的整数，节点也有这个范围里的 ID。

规则：立即后继

key 存在 ID ≥ key 的最小节点上；没有比 key 大的节点就绕回最小的节点（环形）。

例：节点 1、3、4、5、8、10、12、14（$n = 4$）。

key存在原因
23≥ 2 的最小 ID
131412 数值上更近，但不是后继
151没有 ≥ 15 的节点，绕回
  • 查询：只知道后继时沿环传，平均 $O(N)$ 条消息；加捷径后每节点 $O(\log N)$ 个邻居、查询 $O(\log N)$ 条消息（Chord）。
  • 节点离开：每个节点记两个后继并定期 ping。立即后继走了，就把第二后继升为立即后继，再问它的后继作为新的第二后继。只记一个的话环会断。
DHT 节点 ID 为 1、3、4、5、8、10、12、14。key 13 和 key 15 分别存在哪个节点？
  1. 12，14
  2. 14，1
  3. 14，14
  4. 12，1
13 的后继是 14；15 没有后继，绕回 1。A 把「最接近」当成数值最近。

题型 6　DNS 基础与 Socket 概念 ★★

DNS 基础

  • DNS 既是分布式数据库，也是应用层协议。端口 53，一般查询用 UDP，响应过大或区域传送用 TCP，所以「用哪个」答两者都用。
  • 额外服务：主机别名、邮件服务器别名、负载分配（一个名字对应一组 IP，轮换返回顺序）。
  • 为什么不集中：单点故障、离远处用户时延高、扩展不了（课本还有：维护量太大）。

Socket（不考代码，考概念）

socket 是应用进程和传输层之间的门：门以上由开发者控制，门以下由操作系统控制。SOCK_DGRAM = UDP，SOCK_STREAM = TCP。

UDP socketTCP socket
连接不建立，直接发客户 connect()，服务器 accept()
目的地址每个分组都带（sendto）建连时给一次
收recvfrom() 同时拿到发送方地址recv()
服务器 socket 数1 个，所有客户共用1 个欢迎 socket + 每个客户 1 个连接 socket

本周 Tutorial（Wireshark 看 HTTP）

  • 清空缓存后第一次 GET 没有 If-Modified-Since，回 200；第二次带上，回 304，不带内容。
  • HTTP Basic 认证：先回 401；再请求时带 Authorization: Basic ...。这串只是 Base64 编码，解码就是 用户名:密码。编码不是加密，所以需要 TLS。

每条连接一个连接 socket，和主机数无关。

考前速记

  1. 迭代 8 步：本地 → 根 → TLD → 权威 → A 记录；迭代是最佳实践，递归上层负载重。
  2. A 给 IP；NS 给服务器名（配一条 A，TLD 回 2 条）；CNAME 给真名；MX 给邮件服务器。
  3. C/S $\max(NF/u_s, F/d_{\min})$；P2P $\max(F/u_s, F/d_{\min}, NF/(u_s+\sum u_i))$；P2P 趋于 $F/u$。
  4. 本地 DNS 不属于层次结构；不集中的原因：单点故障、时延、扩展；DNS 端口 53，UDP 和 TCP 都用。
  5. BitTorrent：rarest first；前 4 名每 10 s；乐观疏通每 30 s；tracker 只记用户。
  6. DHT：≥ key 的最小 ID，绕回；$O(N)$ → 捷径 $O(\log N)$；记两个后继防断环。
  7. TCP 服务器：1 欢迎 socket + 每连接 1 个；UDP 服务器 1 个 socket，每个分组带地址。
  8. Basic 认证只是 Base64 编码；401 要认证。
