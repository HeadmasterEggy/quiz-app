题型 1　QUIC ★★★

趋势：把传输层功能搬到应用层，跑在 UDP 上。QUIC 是跑在 UDP 之上的应用层协议（RFC 9000，2021 年 5 月），HTTP/3 就用它。

层HTTP/2 over TCPHTTP/3
应用HTTP/2精简的 HTTP/2 = HTTP/3
TLSQUIC（加密 + 可靠 + 拥塞控制）
传输TCPUDP
  • 建连：可靠性、拥塞控制、认证、加密的状态在 1 个 RTT 内建好（连过的服务器 0-RTT）；TCP + TLS 要两次握手。
  • 多流：一个连接复用多个流，每个流独立的可靠传输和安全，共用一个拥塞控制。

队头阻塞（Sample exam Q2）

TCP 只有一条按序交付的字节流。中间丢一个段，后面所有字节（哪怕属于别的 HTTP 请求）都要在缓冲区里等它重传。HTTP/2 把多个请求复用在一条 TCP 上，正好放大了问题。QUIC 每个流单独做可靠传输，一个流丢包只影响这个流。

官方答案只认 TCP

HTTP/1.1 在应用层也有一种 HOL（W03：小对象排在大对象后面），但题目问的是协议层因丢包重传造成的 HOL。

Connection ID、包号、帧

机制要点
Connection IDTCP 用四元组、UDP 用二元组标识；QUIC 用 Connection ID。4G 换 Wi-Fi，IP 变了，TCP 断，QUIC 平滑迁移
Packet number单调递增、永不重复，重传也用新包号 → 没有 TCP 那种 RTT 测量歧义
Stream 帧 Offset + Length保证流内顺序。丢包检测（包号）和重组（offset）分开
MAX_DATA / MAX_STREAM_DATA两层流控：连接级和流级（带 STREAM 的是流级；讲义 p50 写反了）
PING、CONNECTION_CLOSE检查对方是否在；连接正在关闭

拥塞控制与超时

$$\text{PTO} = smoothed\_rtt + \max(4\cdot rttvar,\ kGranularity) + max\_ack\_delay$$

比 TCP 的 EstimatedRTT + 4·DevRTT 多两项：kGranularity（定时器粒度 1 ms，防止超时过短）和 max_ack_delay（接收方最多延迟 ACK 多久）。慢启动、拥塞避免、恢复期减半都和 TCP 类似；持续拥塞（一段足够长时间内在途分组全丢）→ 回到慢启动。

下面哪个协议存在队头阻塞（head-of-line blocking）问题？
  1. UDP
  2. TCP
  3. QUIC
  4. HTTP
TCP 一条按序字节流；QUIC 每个流独立。

题型 2　5G 核心网功能 ★★★

RAN（无线接入网）：设备 UE + 无线信道 NR + 基站 gNodeB，是第一跳，一个运营商控制。核心网：一个核心多个 RAN，全 IP，控制面和用户面分开（CUPS），主要是控制面服务。

功能面管什么
UPF唯一的用户面在 UE 和互联网之间中继流量；和基站之间的隧道；策略执行、计量、QoS 监管
AMF控制接入和移动：可达性、移动性管理、接入授权、位置服务
SMF控制会话：分配 IP、选 UPF、QoS 控制
AUSF控制认证设备
UDM控制用户身份，生成认证凭据
UDR / UDSF控制静态签约信息 / 非结构化数据

记法：AMF 接入移动，SMF 会话；AUSF 认证，UDM 身份；UPF 是唯一的用户面。

5G 核心网中负责给设备分配 IP 地址、选择 UPF 的是？
  1. AMF
  2. SMF
  3. UDM
  4. UDR
S = Session。AMF 管接入和移动。

题型 3　入网、GTP-U 隧道、5G 切换 ★★

接口与隧道

接口两端
N1 / N2UE ↔ AMF / 基站 ↔ AMF
N3基站 ↔ UPF（用户面隧道）
N4SMF ↔ UPF
N6UPF ↔ 互联网

GTP-U 隧道：用户 IP 数据报 / GTP-U / UDP / 外层 IP。设备 z、基站 y、UPF x、发送方 w：UPF → 基站一段外层 x → y，内层始终 w → z。和 Mobile IP 一个思路：设备移动只改隧道端点，IP 地址 z 不变。

入网两阶段

  1. 注册：设备向网络认证，网络也向设备认证（双向）。AMF 起关键作用，经 AUSF 认证、更新 UDM。身份靠 SIM 卡里和归属网络共享的密钥。
  2. PDU 会话建立：分配 IP，建到 UPF 的数据面路径（AMF 找 SMF，SMF 让 UPF 建会话）。

Wi-Fi 内的移动

ESS = 多个 BSS、同一三层子网、同一 SSID。在 ESS 内换 BSS 只需快速重新认证，IP 不变，交换机自学习更新 MAC 所在端口，不需要 Mobile IP。

5G 切换（七步）

  1. 源基站选目标基站，发 Handover Request。
  2. 目标基站预分配无线时隙，回 HR ACK。
  3. 源基站告诉设备新基站的信息，设备可以经新基站发送。
  4. 源基站把收到的数据报转发给目标基站（不丢包）。
  5. 目标基站通知 AMF、SMF；SMF 让 UPF 把隧道端点改到目标基站。
  6. 目标基站确认完成，源基站释放资源。
  7. 数据经新隧道走。

UPF 发 end marker 标记旧隧道最后一个包；UPF 是固定锚点（同 W11 锚点 FA、锚点 MSC）。

关于 5G 切换，正确的是？
  1. 源基站选目标基站并发请求
  2. 切换中源基站把数据转给目标
  3. SMF 让 UPF 改隧道端点
  4. 切换后设备换一个新 IP 地址
设备 IP 不变，变的是隧道端点。

题型 4　LTE 下行公平分配（Tutorial） ★★

A、B、C、D 独占信道时速率 10、5、2.5、1 Mbps，每个时隙每个频率可给任一节点，数据无限。设各分到 $n_i$ 个时隙、共 N 个。

解法步骤
  1. 写出「每个节点数据量」= $R_i n_i$ 之间的约束。
  2. 全部用 $n_1$ 表示，求和 = N，解出 $n_1$。
  3. 平均速率 = $\sum R_i n_i / N$。

数据量完全相等：$10n_1 = 5n_2 = 2.5n_3 = n_4$ → $n_2 = 2n_1, n_3 = 4n_1, n_4 = 10n_1$，$n_1 = N/17$。

$$\bar R = \frac{10\cdot1 + 5\cdot2 + 2.5\cdot4 + 1\cdot10}{17} = \frac{40}{17}\approx 2.35\ \text{Mbps}\qquad\text{速算：}\ \frac{4}{\sum 1/R_i} = \frac{4}{1.7}$$

每个节点只拿 10/17 ≈ 0.59 Mbps，最慢的 D 占了 10/17 的时隙。

A 最多是其他任一节点的 2 倍：$10n_1 = 2\cdot5n_2 = 2\cdot2.5n_3 = 2n_4$ → $n_2 = n_1, n_3 = 2n_1, n_4 = 5n_1$，$n_1 = N/9$，$\bar R = 25/9 \approx 2.78$ Mbps。

公平要求平均速率
不要求（全给 A，不公平）10 Mbps
时隙数相等4.625 Mbps
A ≤ 2 × 其他25/9 ≈ 2.78 Mbps
数据量完全相等40/17 ≈ 2.35 Mbps

公平要求越严，总吞吐越低。

Tutorial：两台设备能共用一个转交地址吗？

能，如果 COA 是外地代理的地址：外层目的 = COA（共享），外地代理解封装后看内层目的（各自的永久地址）区分。设备自己拿的「同址转交地址」不能共享。

同上，数据量完全相等时，D 占了多少比例的时隙？
  1. 1/17
  2. 4/17
  3. 10/17
  4. 1/4
$n_4 = 10 n_1 = 10N/17$。

题型 5　蓝牙、卫星、IoT ★★

蓝牙

无线 ad hoc：没有 AP，设备要从零互相发现、组网，所以协议栈和互联网不同（没有网络层、传输层；L2CAP 提供可靠性、流控、分段）。

要点说明
piconet直径 < 10 m，最多 8 个：1 个 central + 最多 7 个 peripheral
通信只在 central 和 peripheral 之间，peripheral 之间不能直接通信
地址 / 频段唯一 48 位地址；2.4 GHz ISM
信道经典 79 个（1 MHz），BLE 40 个（3 广播 + 37 数据）
访问TDM，时隙 625 μs；central 轮询 peripheral
跳频每个时隙换频率；减少干扰的影响：被占的信道只偶尔出现，丢了下个时隙换频率重传

GEO vs LEO

GEOLEO
相对地面静止移动，约 27 000 km/h
高度约 36 000 km550–1200 km
RTT约 800 ms（不适合 VoIP）约 30 ms
覆盖单颗大单颗小，要星座，有星间链路 ISL
可见时间一直5–15 分钟

bent pipe：只经过一颗卫星转发；天上的网络：经过多颗卫星，卫星之间要路由。

IoT

无线必须；几米到几公里；几百 bps 到约 1 Mbps；能耗：无外部电源工作约 10 年。短距离 Wi-Fi、BLE、Zigbee；低功耗广域 LoRaWAN、LTE-M；传统广域 4G / 5G。

关于蓝牙 piconet，正确的是？
  1. 最多 1 个 central 加 7 个 peripheral
  2. peripheral 之间可以直接通信
  3. 每个设备有唯一的 48 位地址
  4. 工作在 2.4 GHz 的 ISM 频段
只有 central 和 peripheral 之间通信。

考前速记

  1. 有 HOL 的是 TCP；QUIC 每个流独立可靠，共享拥塞控制。
  2. QUIC：应用层、UDP 上、1-RTT / 0-RTT；Connection ID 迁移；包号单调、重传用新号；连接级 + 流级两层流控。
  3. PTO = srtt + max(4·rttvar, 1 ms) + max_ack_delay；持续拥塞回慢启动。
  4. CUPS；UPF 唯一用户面；AMF 接入移动；SMF 会话、IP、选 UPF；AUSF 认证；UDM 身份。
  5. 入网：注册（双向认证）+ PDU 会话（分 IP、建路径）；GTP-U / UDP 隧道在 N3。
  6. 5G 切换：源选目标 → 预分配 → 设备切 → 源转发 → SMF 让 UPF 改隧道 → 释放；IP 不变。
  7. LTE：数据相等 40/17 ≈ 2.35，A ≤ 2× 为 25/9 ≈ 2.78；公平越严吞吐越低。
  8. 蓝牙 1 + 7、48 位、79 信道、625 μs、跳频抗干扰；GEO 800 ms，LEO 30 ms、星座、5–15 分钟。
  9. ESS 同子网同 SSID；IoT 低功耗广域 LoRaWAN、LTE-M；COA 可共享（外地代理地址）。
