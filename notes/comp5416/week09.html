题型 1　按块播放：几块按时、缓冲几块、最小起播 ★★★

视频固定码率，每块播放时长 Δ。服务器在 $t_0, t_0+\Delta, \dots$ 依次发出各块，网络时延会变，到达时间不规则。开播后每块在前一块之后 Δ 播放。

$$\text{从 } s \text{ 起播：第 } k \text{ 块播放时刻} = s + (k-1)\Delta\qquad \text{按时} \iff \text{到达} \le \text{播放时刻}$$
三类问题的做法
问题做法
从 s 起播，几块按时每块比较「到达时间」和 $s + (k-1)\Delta$
缓冲里最多几块在每个播放时刻数「已到达、还没轮到播放」的块
最小起播时刻每块算「到达时间 − $(k-1)\Delta$」，取最大值

题型 2　HTTP 流：播放与卡顿时长 ★★★

符号意思
B客户端应用缓冲总容量
Q开播前要先缓冲的比特数（起播门槛，不是容量）
r视频消耗速率
x服务器发送速率（恒定，缓冲没满就一直发）

播放时缓冲净变化率 = x − r。x < r 时播放和卡顿交替：

$$T_{\text{play}} = \frac{Q}{r - x}\qquad T_{\text{freeze}} = \frac{Q}{x}\qquad \text{播放占比} = \frac{x}{r}$$
  • 播放期：缓冲从 Q 以 r − x 减少，到 0 就卡。
  • 卡顿期：缓冲以 x 重新攒到 Q 再播。
  • 播放占比和 Q 无关：加大 Q 只让每次播放、每次卡顿都更长。

例：Q = 1 Mb，r = 2 Mbps，x = 1.5 Mbps → 播放 2 s，卡顿 0.67 s，占比 75%。

陷阱

Q 和 B 别混：播放 / 卡顿时长只用 Q；B 只在算「什么时候填满」时用。卡顿时长分母是 x，不是 r − x。

HTTP 流，Q = 1 Mb，r = 2 Mbps，x = 1.5 Mbps。每次卡顿多久？
  1. 0.50 s
  2. 0.67 s
  3. 1.00 s
  4. 2.00 s
$Q/x = 1/1.5$。D 是播放时长 $Q/(r-x)$。

题型 3　HTTP 流：缓冲填满时间 ★★

x > r，缓冲初始为空：

$$t_f = \frac{Q}{x} + \frac{B - Q}{x - r}$$
  1. 先以 x 攒到 Q：$Q/x$。
  2. 开播后以净速度 x − r 填剩下的 B − Q。
  3. 填满后服务器停发，实际发送速率降到 r。

例：B = 4 Mb，Q = 1 Mb，x = 3 Mbps，r = 2 Mbps → $1/3 + 3/1 \approx$ 3.33 s。

HTTP 流，B = 4 Mb，Q = 1 Mb，x = 3 Mbps，r = 2 Mbps，缓冲初始为空。缓冲什么时候填满？
  1. 1.33 s
  2. 2.00 s
  3. 3.33 s
  4. 4.00 s
$1/3 + (4-1)/(3-2)$。A 是 $4/3$，忘了开播后净速度只有 1。

考前速记

  1. 第 k 块播放时刻 = 起播 + (k−1)Δ；按时 ⟺ 到达 ≤ 播放时刻。
  2. 最小起播 = max(到达 − (k−1)Δ)；推迟起播让更多块按时，缓冲可能更满。
  3. 缓冲里的块 = 已到达、还没播放的块。
  4. x < r：播放 Q/(r−x)，卡顿 Q/x，占比 x/r 与 Q 无关。
  5. x > r：填满 Q/x + (B−Q)/(x−r)。Q 是门槛，B 是容量。
