题型 1　数 RTT ★★★

RTT：一个小分组从客户到服务器再回来的时间。网页 = 1 个基础 HTML + 若干引用对象（图片、脚本），每个对象单独请求。

非持久 HTTP 取一个对象

  1. 1 RTT 建 TCP 连接；
  2. 1 RTT 发请求、收到响应开头；
  3. 再加文件传输时间。
$$\text{一个对象} = 2\,\text{RTT} + \text{传输时间}$$
非持久 HTTP持久 HTTP
一条 TCP 连接最多传一个对象，传完就关传多个对象，连接保持
每个后续对象重新建连，2 RTT1 RTT

通用公式（1 个 HTML + $n$ 个对象，最多 $k$ 条并行，忽略传输时间）

方式总 RTT
非持久，串行$2 + 2n$
非持久，最多 $k$ 条并行$2 + 2\lceil n/k \rceil$
持久，最多 $k$ 条并行$2 + \lceil n/k \rceil$
持久 + 流水线（不限并行）$3$
解法步骤
  1. 基础 HTML 永远先花 2 RTT（建连 + 请求）。
  2. 引用对象分几轮：有并行上限就是 $\lceil n/k \rceil$ 轮，串行就是 $n$ 轮。
  3. 每轮：非持久 2 RTT，持久 1 RTT。
  4. 浏览器不知道 IP 时，先把 DNS 查询经过的每台服务器的 RTT 加在最前面（W05 tutorial 题型）。
  5. 题目给了传输时间，就在每个对象后面加上。

例题：1 个 HTML + 10 张图，$k = 5$

  • 非持久串行：$2 + 2\times10 = 22$ RTT
  • 非持久并行：2 轮 × 2 RTT，$2 + 4 = 6$ RTT
  • 持久并行：2 轮 × 1 RTT，$2 + 2 = 4$ RTT
  • 持久流水线：3 RTT
陷阱

持久 HTTP 不要一律答 3 RTT。题目给了「最多 $k$ 条并行」且 $n > k$ 时要分轮。

页面含 1 个 HTML 和 10 张图，最多 5 条并行 TCP 连接，使用持久 HTTP（无流水线），忽略传输时间。共需多少 RTT？
  1. 3
  2. 4
  3. 6
  4. 12
HTML 2 RTT；10 张图分 2 轮，每轮 1 RTT；共 4。A 忘了并行上限，C 是非持久。

题型 2　HTTP 状态码与消息格式 ★★★

状态码在响应消息第一行，如 HTTP/1.1 200 OK。首位：2xx 成功，3xx 重定向，4xx 客户端出错，5xx 服务器出错。

状态码意思
200 OK成功，对象在消息里
301 Moved Permanently对象永久搬家，新地址在 Location: 首部
304 Not Modified条件 GET 的回答：缓存副本仍最新，不带对象
400 Bad Request服务器看不懂这条请求
404 Not Found请求没问题，但服务器上没有这个文档
505 HTTP Version Not Supported不支持这个 HTTP 版本

请求消息与方法

纯 ASCII，每行 \r\n 结尾，单独一行 \r\n 表示首部结束。第一行是请求行：方法、URL、版本。

方法作用版本
GET请求对象（表单也可放在 URL 里：?q=new）1.0
POST表单内容放在实体体里上传1.0
HEAD只要首部，不要对象1.0
PUT上传文件到 URL 指定位置1.1 新增
DELETE删除 URL 指定文件1.1 新增
下列状态码与含义对应正确的是？
  1. 200：请求成功，对象在消息中
  2. 400：服务器上找不到这个文档
  3. 404：服务器上找不到这个文档
  4. 505：不支持该 HTTP 协议版本
400 是「服务器看不懂请求」，不是找不到。

题型 3　TCP vs UDP 提供什么 ★★★

服务TCPUDP
可靠传输✔✘
流量控制（不淹没接收方）✔✘
拥塞控制（网络过载时减速）✔✘
面向连接✔✘
时延保证✘✘
最低吞吐量保证✘✘
安全（加密）✘✘
陷阱
  • 最后三行：TCP 和 UDP 都不保证。「TCP 保证最低吞吐量」一律错。
  • 要加密就在 TCP 上加 SSL/TLS，SSL 属于应用层（应用调 SSL 库，SSL 库再用 TCP socket），别因为它「提供加密的 TCP 连接」就选传输层。

应用的四种需求

  • 数据完整性：文件、Web、邮件要 100% 可靠；音视频能容忍少量丢失。
  • 时延：网络电话、互动游戏要 100 ms 级。存储视频能缓冲，只要几秒级。
  • 吞吐量：多媒体要最低吞吐量；文件传输是「弹性应用」。互动游戏吞吐量要求很低（几 kbps）但时延很严：吞吐量和时延是两回事。
  • 安全。

进程靠 IP 地址 + 端口号找到（光有 IP 不够），通过 socket 收发。端口要背：HTTP 80，SMTP 25，DNS 53，FTP 控制 21 / 数据 20。

TCP 和 UDP 都不提供的是？
  1. 可靠传输
  2. 时延保证
  3. 最低吞吐量保证
  4. 加密
可靠传输 TCP 提供；其余三个两者都不提供。

题型 4　Web 缓存与条件 GET ★★

浏览器把请求先发给缓存（代理服务器）：有就直接返回；没有就去源服务器取、存一份再返回。缓存对浏览器是服务器，对源服务器是客户，通常由 ISP（大学、公司）部署。最大价值是减少机构接入链路的流量。

$$\text{接入链路利用率} = \frac{(1-h)\times\text{数据率}}{\text{链路速率}},\qquad \text{平均时延} = (1-h)\,D_{\text{源}} + h\,D_{\text{缓存}}$$

$h$ 是命中率。

例题（讲义）

接入链路 1.54 Mbps，到源服务器 RTT 2 s；对象 100 kbits，每秒 15 个请求 → 需求 1.5 Mbps。

方案接入链路利用率时延
什么都不做$1.5/1.54 \approx 0.97$排队爆炸，几分钟
链路升到 154 Mbps约 0.01约 2 s，但贵
装缓存，$h = 0.4$$0.6\times1.5/1.54 = 0.58$$0.6\times2.01 + 0.4\times$ 毫秒 $\approx 1.2$ s

结论：装缓存比升级链路时延还低，而且便宜。

条件 GET

缓存请求时带 If-modified-since: <副本日期>。没改过 → 304 Not Modified，不带对象；改过 → 200 OK + 新对象。每个请求都要问一声，所以每个都花 1 RTT：

$$\text{总时间} = N\cdot\text{RTT} + N\,(1-h)\,d_{\text{trans}}\quad(h = \text{没改过的比例})$$
RTT = 45 ms，服务器发一个对象要 2 ms。客户依次发 60 个带 If-Modified-Since 的请求，其中 70% 的对象没改过。总时间是？
  1. 2700 ms
  2. 2712 ms
  3. 2736 ms
  4. 2784 ms
$60\times45 + 60\times0.3\times2 = 2700 + 36 = 2736$ ms。A 忘了传输时间；D 是把 70% 当成要传的。

题型 5　HTTP/2 与队头阻塞 ★★

HTTP/1.1 的问题：一条连接上流水线发多个 GET，但服务器按 FCFS 回。大对象排在前面，后面的小对象都得等，这是应用层队头阻塞（HOL）。

1 个大对象 O1（100 单位）+ 3 个小对象（各 1）O1 完成小对象完成
HTTP/1.1（FCFS）100101、102、103
HTTP/2（分帧交错）1031、2、3

HTTP/2（RFC 7540）：

  • 方法、状态码、大部分首部和 1.1 一样。
  • 分帧：对象切成二进制帧，交错发送。
  • 流：一条 TCP 连接里多个双向的流。
  • 按客户指定优先级发，不必 FCFS。
  • 服务器推送：客户还没请求，服务器就推过去。
陷阱

HTTP/2 解决不了 TCP 层的队头阻塞：所有流共用一条 TCP 连接，丢一个段大家都等重传。这要 QUIC 才解决（W12；样卷 Q2 答 TCP）。

关于 HTTP/2，正确的是？
  1. 对象切成帧交错发送，缓解队头阻塞
  2. 改掉了 HTTP/1.1 的方法和状态码
  3. 支持服务器主动推送对象给客户
  4. 彻底消除了 TCP 丢包造成的阻塞
B 错：方法和状态码基本不变。D 错：TCP 层 HOL 要 QUIC 解决。

题型 6　架构、Cookie、HTTP / SMTP / FTP 对比 ★★

两种架构

客户/服务器P2P
服务器一直在线、固定 IP没有一直在线的服务器
端之间客户之间不直接通信对等方直接通信
扩展加服务器自扩展：新用户带来需求也带来上传能力

「客户 / 服务器」是进程的角色：发起通信的是客户进程，等着被联系的是服务器进程。

HTTP 无状态与 Cookie

HTTP 无状态：服务器不记得客户之前请求过什么（维护状态复杂，崩溃后状态会对不上）。Cookie 的四个组成部分：① 响应里的 Set-cookie 首部；② 之后请求里的 cookie 首部；③ 用户电脑上由浏览器管理的 cookie 文件；④ 网站后端数据库。用途：授权、购物车、推荐；问题：隐私。

  • SMTP：TCP 25；发件服务器直接连收件服务器；持久连接；消息必须 7 位 ASCII；CRLF.CRLF 结束；命令 HELO → MAIL FROM → RCPT TO → DATA → QUIT。
  • 取信用 POP3 / IMAP / HTTP，SMTP 只负责送到对方服务器。POP3 下载到本地、跨会话无状态；IMAP 邮件留在服务器、可建文件夹、跨会话有状态。

SMTP 把邮件推给对方服务器；HTTP 由客户把对象从服务器拉回来。

考前速记

  1. HTML 2 RTT；非持久每轮 2 RTT，持久每轮 1 RTT；$k$ 条并行分 $\lceil n/k \rceil$ 轮；流水线 3 RTT。DNS 的 RTT 加在最前。
  2. 200 成功；301 永久搬家（Location）；304 没改过（不带对象）；400 看不懂；404 不存在；505 版本不支持。
  3. TCP / UDP 都不保证时延、吞吐量、安全；SSL 在应用层。
  4. 缓存利用率 $(1-h)\times$ 需求 / 链路；缓存比升级链路便宜更快；缓存既是客户也是服务器。
  5. 条件 GET：每个请求 1 RTT，只有改过的加传输时间。
  6. HTTP/2：二进制分帧、流、优先级、服务器推送；TCP 层 HOL 仍在。
  7. 端口 80 / 25 / 53 / 21 / 20；HTTP 无状态 pull，SMTP push，FTP 有状态带外。
  8. Cookie 四件：Set-cookie、cookie 首部、cookie 文件、后端数据库。PUT、DELETE 是 1.1 新增。
