题型 1　TCP socket vs UDP socket ★★

Socket 是应用进程和传输层之间的门：门以上由应用开发者控制，门以下（传输层及以下）由操作系统控制。

TCP socketUDP socket
创建socket(AF_INET, SOCK_STREAM)socket(AF_INET, SOCK_DGRAM)
先建连接要（三次握手）不要
发送带不带对方地址不带：send()每次都带：sendto(msg, (ip, port))
接收recv(n) 只返回数据recvfrom(n) 返回 (数据, 发送方地址)
服务器 socket 数1 个欢迎套接字 + 每个客户 1 个连接套接字1 个服务所有客户
数据形式字节流数据报

这就是 W05「UDP 二元组、TCP 四元组」在代码里的样子。

两种 TCP 套接字的分工
  • 欢迎套接字（serverSocket）：只「接门铃」，一直 LISTEN，不收发数据。
  • 连接套接字（connectionSocket）：每个客户一个，由四元组区分，真正收发数据。关掉它不影响欢迎套接字。
关于 UDP socket 程序，正确的是？
  1. 服务器不需要 listen 和 accept
  2. 客户端每次发送都写服务器地址
  3. 服务器从 recvfrom 得到客户地址
  4. 服务器为每个客户新建 socket
UDP 服务器一个 socket 服务所有客户。

题型 2　调用对应的 TCP 动作 ★★

调用谁调对应
bind(('', 12000))服务器定下端口；'' 表示本机所有网卡
listen(1)服务器进入 LISTEN
connect()客户端发起连接，触发三次握手
accept()服务器阻塞到有客户完成握手，返回新的连接套接字和客户地址
close()双方发 FIN；服务器关的是这个客户的连接套接字
  • 客户端不调用 bind()，操作系统自动分配临时源端口。
  • Python 3 socket 只收发 bytes，字符串要 encode() / decode()。
TCP 服务器调用 accept() 返回的是？
  1. 原来的欢迎套接字
  2. 新的连接套接字和客户地址
  3. 客户端发来的第一段数据
  4. 客户端使用的源端口号
accept 在握手完成后返回一个专门服务这个客户的新 socket。

题型 3　Lab 问题与 Wireshark ★

问题答案为什么
先运行谁服务器TCP 客户端一启动就 connect，没人 LISTEN 就握手失败
同一台机器 serverName 填127.0.0.1环回地址（localhost 也行）
连别人的机器要改客户端里的服务器 IP服务器 bind('') 已监听所有网卡
服务器没开TCP：connect() 立刻失败（对方回 RST）；UDP：sendto 不报错，客户端卡在 recvfromUDP 发出去就不管了

Wireshark 看到什么

TCP 版（客户端发 aaaaa，服务器回 AAAAA）：

  1. C → S [SYN]，相对序号 Seq = 0
  2. S → C [SYN, ACK]，Ack = 1
  3. C → S [ACK]，握手完成
  4. C → S [PSH, ACK] aaaaa，Seq = 1，Len = 5（SYN 占了序号 0）
  5. S → C [ACK]，Ack = 6
  6. S → C [PSH, ACK] AAAAA
  7. [FIN, ACK]、[ACK] 关闭；服务器回完就 close，往往服务器先发 FIN

UDP 版：只有两个数据报（请求和回复），没有 SYN / ACK / FIN，没有序号，首部 8 字节。这是「UDP 无连接、首部小」最直接的证据。

Wireshark 显示客户端发了 Seq = 1、Len = 5 的数据段。服务器回的确认号是？
  1. 1
  2. 5
  3. 6
  4. 7
ACK = 下一个期望字节 = 1 + 5。

题型 4　期中讲评题型 ★★

4.1 存储转发车队

20 辆车，收费站每 1 s 服务 1 辆，两站相距 200 km，车速 10 km/s，车队到齐才开始服务。第一辆车离开后多久在下一站开始被服务？

$$\underbrace{19\times1}_{\text{后面 19 辆服务完}} + \underbrace{200/10}_{\text{最后一辆开过去}} = 39\ \text{s}$$

第一辆车 20 s 就到了，但要等整个车队到齐：这就是存储转发。

4.2 干扰信息

  • 链路 3 km，传播速度 $3\times10^8$ m/s，分组 16000 bit，速率 1000 Mbps。传播时延 $= 3000/3\times10^8 = 1.0\times10^{-5}$ s。分组长度和速率是干扰。
  • 电路交换每人 20 Mbps、链路 100 Mbps；分组交换传输时 20 Mbps、30% 时间在传。「一个用户传输时占链路的比例」两种都是 0.2，30% 只影响能支持多少人。

4.3 瓶颈与利用率

4 对共享 R = 300 Mbps，$R_s = 10$，$R_c = 90$。每对 $\min(10, 75, 90) = 10$ Mbps；客户端链路利用率 $10/90 = 0.11$。

4.4 信道博弈

  • 对称：独占 +16，都发 −8。$E[\text{发}] = 16(1-p_2) - 8p_2 = 16 - 24p_2 > 0 \iff p_2 < 2/3$。
  • 不对称：只有 1 发，1 得 24；只有 2 发，2 得 16；都发时 1 得 −8、2 得 −4。
    让用户 1 无差异：$24(1-p_2) - 8p_2 = 0 \Rightarrow p_2 = 3/4$；让用户 2 无差异：$16(1-p_1) - 4p_1 = 0 \Rightarrow p_1 = 4/5$。
    混合均衡 (4/5, 3/4)；纯策略均衡 (发, 不发)、(不发, 发)。
陷阱

$p_1$ 从用户 2 的收益解出来，$p_2$ 从用户 1 的收益解出来。选项里 (3/4, 4/5) 就是搞反的。

20 辆车的车队，收费站每 1 s 服务 1 辆，两站相距 200 km，车速 10 km/s，车队到齐才服务。第一辆车离开收费站后，多久在下一站开始被服务？
  1. 20 s
  2. 21 s
  3. 39 s
  4. 40 s
等后面 19 辆服务完（19 s）+ 最后一辆开 20 s。

考前速记

  1. TCP 服务器：1 欢迎套接字 + 每客户 1 连接套接字；UDP 服务器 1 个。
  2. connect() 触发握手；accept() 在握手完成后返回新的连接套接字。
  3. UDP sendto / recvfrom 每次带地址；TCP send / recv。
  4. 先启动服务器；本机用 127.0.0.1；客户端不 bind。
  5. Wireshark：TCP 数据从 Seq 1 开始（SYN 占 0）；UDP 只有两个数据报。
  6. 车队到齐才服务：$(n-1) \times$ 服务时间 + 路程；传播时延与分组长度无关；混合均衡「让对方无差异」。
